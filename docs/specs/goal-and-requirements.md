# Todo List — 开发任务的结构化清单

## Overview

一个单人使用的桌面待办应用，专门用于管理软件开发任务。左栏最上方是一个叫"待办"的虚拟项目，用来保存不属于任何项目的全局待办；下面才是项目列表。任务可以属于某个项目（可以再按 **项目 > 模块 > 子模块** 两级归类），也可以留在"待办"里，两边可以互相移动。每个任务还可以拆出一层子任务。主视图是一张按模块分组的表格（在"待办"里因为没有模块，就是一张平铺表格）：模块与子模块是可折叠的分组行并带完成计数，模块/子模块不再单独占一列（位置即分类）。任务带三态状态（未完成 / 进行中 / 已完成）和优先级（高 / 中 / 低），可以按状态、优先级筛选，组内按优先级排序，每条任务可以附带一段自由文本备注。新任务默认优先级"中"、落进当前选中的范围（没选具体模块时就是"未分类"），回头再归类。数据写在本机 SQLite 文件，不需要账号、网络或服务器。

## Problem

开发中的待办天然是分层的：一个仓库里有若干模块，模块里还有子模块，脑子里记的是"认证模块的 token 刷新还没做"这种带位置的信息。平铺的清单丢掉这层位置，于是要么写成很长一句前缀，要么过两天就不知道这条属于哪里；而用大而全的项目管理工具，又要先登录、建工作区、配字段，记一条任务的成本远高于任务本身。

同时，一件事内部还有步骤（"实现 token 轮换"底下有"处理并发刷新""补过期用例"），工作也有轻重（哪件先做）。这些信息如果只能写进任务标题，标题就会膨胀成一句话论文。

需要的是：结构足够表达"项目/模块/子模块 + 一层子任务"，轻重有三档，输入又足够快——回车一条，默认不问归处，之后按需归类、拆解、提优先级。

## Capabilities

- **项目 / 模块 / 子模块的层次结构** — 可以创建多个项目，每个项目下可以建模块，模块下可以再建子模块（最多两级嵌套）。三级结构在界面上都可新建、改名、删除，**入口统一在左栏的右键菜单**：项目行右键 → 新建模块 / 重命名 / 删除；模块行右键 → 新建子模块 / 重命名 / 删除。
- **左侧栏：待办 + 项目列表** — 左栏最上方固定一行"待办"（虚拟项目，恒存在、不可删除、没有模块），下面才是"项目"分段与项目列表。点哪一项就切到哪个视图。
- **新建项目** — 点「＋ 新建项目」在项目列表下方展开一行输入框，回车创建并切到新项目。点表单外的任何地方或按 Esc 都会**收起并清空**，回到未打开的样子（已输入的文字丢弃；这是一行式的轻量入口，不保留半开的草稿）。
- **范围树** — 项目下可展开模块/子模块树，点某个节点就把主视图限定在该子树，"全部"和"未分类"也是可选节点。节点上的计数是子树的 `已完成/总数`。选中的节点成为视图的根：选子模块时它自己不再缩进。"待办"没有这层树。
- **添加任务** — 输入一行文字、回车即加入**当前范围**：范围是某个模块/子模块时，新任务就落进那个模块/子模块；范围是"全部"或"未分类"时落进"未分类"；在"待办"里则成为一条无项目的全局待办。输入框的提示语跟着范围走（如 `添加到「认证」`），让人在回车前就知道会落到哪里。默认优先级"中"，排在所属分组末尾。
- **子任务** — 任何任务下都可以再拆出**一层**子任务（子任务不能再挂子任务）。入口是父任务行的「＋」：点开后在该父任务下方就地出现输入行，回车保存并可继续添加下一条，Esc 取消，失焦保存非空内容。子任务继承父任务的模块/子模块归属，但有自己的优先级和备注。**子任务的优先级不能高于父任务**：父任务为"低"时，新建子任务也是"低"；父任务降档时，仍高于它的子任务跟着降。父任务行有折叠箭头、默认展开，子任务以缩进 4 个空格的行程跟在其下，不加前缀符号。父任务标题后显示子任务的完成计数 `已完成/总数`；计数按全部子任务算，不随筛选变化。
- **父任务与子任务的状态联动** — 子任务全部完成时，父任务自动变为已完成；反过来，把还有未完成子任务的父任务标为已完成时，先弹窗确认，确认后连同子任务一并完成。手动把父任务退回时子任务不动（“子全完成 → 父已完成”是事件触发的推导，不是恒成立的不变式）；父任务被自动改动时给一条几秒后消失的轻提示，不阻塞操作。只有**被自动改动**的父任务才提示；同时出现多条提示时按先来后到排队显示，不互相顶掉。删除子任务也会触发推导：删掉最后一个未完成子任务后，若剩余子任务（可能为零）全为已完成，父任务自动变为已完成并给出同样的轻提示。
- **表格（主视图）** — 一行一条任务，**固定按模块分组**，界面上没有分组选择器。模块与子模块是可折叠的分组行，带计数（如 `3/7`、`2 个子模块`）；计数**只算父任务**，不含子任务。模块/子模块不单独占列——位置即分类。在"待办"视图里没有模块，也就没有分组行，表格直接就是平铺列表。
- **状态（三态）** — 未完成 / 进行中 / 已完成。状态格里点一下就在三态之间循环（分别是 空框 / 半圆 / 勾）。没有独立的勾选框——一个字段只有一个控件。
- **优先级** — 高 / 中 / 低，默认"中"。表格里是一列，格内点开一个**三档浮窗**选一个，按颜色区分。为什么和状态不一样：状态是三态循环（顺序无歧义，点错了再点回来的代价一样），优先级是"从三档里挑一个"，循环会在低→高之间多走一步；两档以上且无天然顺序的字段，选比循环好。
- **排序** — 每个分组内部先按优先级 高 → 中 → 低，同一优先级内按添加顺序（新的在下）。改优先级会让行移动，这是排序的代价；被移动的那行会在新位置**短暂高亮一下**，免得"行跳走了找不着"。
- **筛选** — 顶部两组可勾选的小标签，与左栏范围叠加生效：
  - **状态**：未完成 / 进行中 / 已完成，默认只勾前两个（即"还剩什么要做"）。取消勾选"已完成"就是隐藏已完成。
  - **优先级**：高 / 中 / 低，默认全勾。
  - **父子筛选**：父任务和子任务分别按同一组条件判断。父任务不命中但子任务命中时，命中子任务仍显示，父任务以灰显行作为层级上下文；二者都不命中才整棵隐藏。
- **已完成的表现** — 当"已完成"标签处于勾选状态时，已完成的行留在原位、文字变灰并加删除线；取消勾选时行消失，但分组行和左侧范围树上的计数仍基于全部任务（如 `3/7`），不会让人误以为任务丢了。
- **归类与跨容器移动** — 任务行尾的"…"菜单里是"移动到 → 待办 / 项目 / 模块 / 子模块"，双向可用：待办里的任务可以派进某个项目的模块，项目里的任务也可以退回待办。子任务跟随父任务，不单独归类。
- **就地编辑任务文字** — 双击任务文字（父任务与子任务都一样）就变成输入框：回车保存、Esc 取消；保存时若为空或只剩空格，则还原原文、不入库。**点别处（失焦）等同于回车保存**——在表格里换焦点是最常见的"我改完了"，丢掉刚打的字比多存一次更糟；Esc 仍是唯一的"不要了"。备注不走这条路，仍是弹窗编辑。
- **备注** — 表里一列单行截断摘要；点该格弹出对话框查看并编辑任意文本。父任务与子任务都有备注。
- **删除** — 删除任务（连同它的子任务）；删除模块/子模块时，里面的任务一并删掉；删除项目时，项目里的所有任务一并删掉。三者都从菜单进入，先弹窗确认并告知涉及的任务数量。删完如果正停在被删的任务范围里：删模块/子模块回到项目「全部」，删项目回到「待办」。删除子任务还会按联动规则推导父任务状态，并按需给出轻提示。
- **本机持久化** — 每次改动立即写入本机 SQLite 文件，重启应用后结构与内容不变。
- **数据安全** — 数据库结构升级前自动生成备份（只保留最近 5 份）；迁移失败时拒绝启动，在窗口里显示原因与备份文件路径，数据库停留在升级前的版本，不会被改到一半。开发版提供「重置数据库」入口，正式版没有这条路径。

## 显示形态的取舍

主视图在"纯表格 / 纯树 / 两者混合"之间选过一轮，结论是**分组表格**：

- 纯表格（分类只是列）层次感弱，结构只能靠左栏树看；
- 纯树（分类是缩进）在单个模块下任务多时退化成一段缩进平铺，且失去列对齐，跨模块比较很难；
- 树状表格（模块本身也当表格行）列不消失，但模块行大半格子空着、缩进挤占列宽，行数明显膨胀；
- **表格 ⇄ 树 双视图切换**明确不做：等于维护两套布局、两套折叠状态，还要同步筛选与选中项，最后两个视图都是半成品。

分组表格用"模块即分组行"把树塞进表格：分类靠缩进与分组行表达，列只留状态、任务、优先级、备注这几样真正需要对齐的信息。这也让"已完成要灰显还是要隐藏"变成一个控件的结果，而不是两个会互相打架的开关。同理，三态状态只有一个循环切换的入口，不再保留独立的勾选框。

分组器后来被去掉：分类维度只有"按模块"是真实需求（看状态有筛选就够），多一个选择器就多一组状态、多一条要维护的渲染分支。代价是失去了"不分组平铺、横向比较各模块未完成"的能力——需要比较时靠筛选与分组行计数的配合。

## Non-Goals

- 多用户、账号、云同步 — 单人为本机工具。
- 跨项目总表 — 不提供把所有项目的任务聚在一张表里的视图；"待办"只装不属于任何项目的任务，不聚合各项目的内容。
- 任务搜索 — 本次不做；分组与筛选已足以定位。
- 拖拽归类 — 归类统一走行尾菜单。
- 子任务的子任务 — 只允许一层。
- 子任务完成计数（如父任务行上的 `1/2`）— 子任务不多，父任务展开就看得见。
- 可切换的分组维度（按状态分组 / 平铺不分组）— 视图固定按模块分组，状态交给筛选。
- 自定义优先级档位或自定义状态值 — 三档状态、三档优先级是固定词汇。

## Tech Notes

| 方面 | 选择 | 理由 |
| --- | --- | --- |
| 应用外壳 | Tauri 2（Rust） | 安装包与内存占用远小于 Electron，桌面应用只需要一个薄壳 |
| 前端 | Vite + TypeScript，原生 DOM，不引入 UI 框架 | 界面仍是"一张表 + 一个分组器 + 一个侧栏"，框架带来的构建与依赖成本大于收益（由我判断，非你指定，可推翻） |
| 数据存储 | SQLite，位于应用数据目录（Windows：`%APPDATA%/todolist/tasks.sqlite`） | 你选的方案：零交互、不怕丢，也为以后任务量变大留余地 |
| 数据访问 | Tauri 命令 + `rusqlite`，前端不直接碰数据库 | 数据读写集中在一处，权限与迁移都只有一条路径 |
| 数据模型 | `project` → `module` → `submodule` → `task`；`task` 持有 `status`（未完成/进行中/已完成）、`priority`（高/中/低）、`note`、`sort_order`、`project_id`（**可空，空即属于"待办"**）、`module_id`/`submodule_id`（可空=未分类）、`parent_id`/`parent_task_id`（可空=顶层任务，仅一层） | 层级只有两级分类 + 一层子任务，外键比通用树结构简单得多；"待办"不是一行真实项目，而用 `project_id` 为空表达，免去一个永远存在的系统记录 |
| 分组、筛选、排序 | 都在前端对已取回的任务做，不落库 | 单个项目的任务量在本机是小规模，前端计算足够快，也避免为每种分组 × 筛选 × 排序组合写查询 |
| 目标平台 | Windows 优先 | 你在这台机器上开发和使用；Tauri 让 macOS/Linux 基本免费，暂不专门验证 |

## Alternatives Considered

同类里已经有一批本地优先的桌面待办，但它们要么已经长成一个体系，要么在别处：

- **Super Productivity**（[repo](https://github.com/super-productivity/super-productivity)）— 本地优先的成熟产品，带时间盒、番茄钟、Jira/GitHub 集成、插件体系。它的复杂度正是这里想避开的：想要的是"打开就记一行"。
- **Vikunja**（[repo](https://github.com/go-vikunja/vikunja)）— 功能最全的自托管待办，但需要服务器和部署，与"不联网、不部署"的前提相反。
- **Tauri + React + SQLite 的一批仿作**（如 [mbenja/tauri-todo-app](https://github.com/mbenja/tauri-todo-app)、[Tanveer-LowCoder/To-Do-MCP](https://github.com/Tanveer-LowCoder/To-Do-MCP)）— 技术栈与这里相同，但都是平铺清单，没有项目/模块/子模块这层结构，也没有分组表格与子任务。
- **Taskwarrior**（[site](https://taskwarrior.org/)）— 能力极强（有优先级与依赖），但只有命令行；需求是带分组表格的桌面窗口。

结论：这个想法没有被现成项目完整覆盖，但它的价值只在"足够小"上——任何一项新能力都应该先问自己是不是在往 Super Productivity 的方向滑。
