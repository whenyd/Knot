## 待决问题

### D1 · 删除模块时，里面的任务去哪？—— **已定：确认后一并删除**

- 结论：删除模块/子模块时，组内任务**真删**（先弹窗告知条数），不退回默认。
- 已同步：`docs/specs/goal-and-requirements.md`「删除」去掉了“（推断）”；`docs/specs/architecture.md` 的 schema 把 `task.module_id` / `submodule_id` 改成 `ON DELETE CASCADE`，并写明为什么需要一条 v2 迁移（v1 已发布为 `SET NULL`，历史条目不能改）。
- 连带结论：删项目同样是“带走它的所有任务”——`project_id` 本来就是 `CASCADE`，无需迁移。

### D2 · 子模块与模块的新建入口 —— **已定：左栏右键菜单**

- 项目行右键 → 新建模块；模块行右键 → 新建子模块。
- 可做：`contextmenu` 在 Tauri 的 webview 里就是普通 DOM 事件，`preventDefault` 掉原生菜单、弹自建菜单即可（与确认框同一套 DOM 层）。

### D3 · 项目名 / 模块名怎么改 —— **已定：右键菜单 + 左栏双击**

- 左栏项目名右键 →「重命名项目」；项目名、模块名、子模块名都可以**双击直接改名**。
- 单击仍是“切换视图”：模块 / 子模块的第一次点击会重绘左栏，原生 `dblclick` 不可靠，改用“同一节点 400ms 内第二次点击”识别；项目名没有单击行为，走原生 `dblclick`。
- 双击只属于结构名，任务标题的双击仍是就地编辑。
- 重命名走**原地输入**：名字本身变成单行 `.side-input`，Enter / 失焦保存、Esc 取消，空值或没改就还原；不弹窗，也不复用任务标题的多行 textarea。

### D4 · 筛选落地时默认视图会变

goal 规定状态标签**默认只勾「未完成」「进行中」**，也就是说筛选做完之后，“已完成”默认**隐藏**，而现在它们一直显示（灰显 + 删除线）。这是规格要求的行为，到时候别当成 bug。

### D5 · 右键不可发现（未确认，建议的补救）

右键菜单没有任何视觉提示，第一次用的人不会知道能右键；纯键盘用户也不友好。建议：同一菜单同时挂在**鼠标悬停时出现的 `⋯` 按钮**上（一个菜单组件、两个触发器），成本很小。**尚未确认。**

### D6 · 国际化 —— **已定：中英双语 + 后端结构化消息**

- 语言入口：状态栏「中文 / English / 跟随系统」三态，默认跟随系统，存 `knot.language.v1`；不新增数据库设置表。
- 文案归属：前端字典 `src/i18n/**`；后端所有 `Err`、`plan_set_status.reason`、`notices` 改为 `Message { key, params }`，由前端翻译；契约文件 `src-tauri/backend-keys.json`。
- 英文术语：Todo / Doing / Done、High / Medium / Low、Default、My Tasks；稳定 token（`todo/doing/done`、`high/mid/low`）与 `data-*` 不翻译。
- 日期：显示层本地化，存储与排序继续用 `YYYY-MM-DDTHH:MM`。
- 注释：源码注释英文化；已发布迁移只改注释、SQL 一字不动（CLAUDE.md 的表述同步放宽）。
- 文档：中文为权威版本，英文镜像与中文相邻；术语表在 `docs/i18n/glossary.md`。
- 安装包：NSIS 简中 + 英文并显示语言选择器；MSI 的 `zh-CN` 需实测，失败则退回英文或只发布 NSIS。

阶段 4 实现决策：

- 子任务入口用父任务行的 `＋` 行内输入，回车后输入行保持打开，可连续添加；父任务行有折叠箭头、默认展开，收起状态只在本次会话内记住。
- 聚合按字面规则实现：零个子任务时 `all()` 为真，所以删除最后一个未完成子任务会让父任务变 `done`。
- 子任务优先级以父任务为上限：新建时默认"中"、父任务更低则跟随；父任务降档时级联下调仍高于它的子任务，旧数据由 v3 迁移归一。
- `create_task` / `delete_task` 的返回结构改为带 `notices` 的对象；只有父任务被自动改动时才产生提示。
- 轻提示改为 FIFO 队列，一次显示一条（每条 2s）。

阶段 6 实现决策：

- 备份只在 `0 < user_version < 最新版本` 时生成；新库与同版本启动不备份。备份失败即停止迁移。

阶段 14 实现决策：

- 只做模块这一层：子模块的归属与顺序在用户心里是“跟着模块走”的，单独拖会让左栏多一维隐藏状态；`sort_order` 本来就按项目内模块排队，直接复用。

- 插入位置按模块行中线算：指针在第 i 个模块上半 → 插到它之前；下半 → 插到它之后（等价于第 i+1 个之前）；最后一行下半 → 末尾。子模块行不画线，落在它上面时按所属模块的位置算。
