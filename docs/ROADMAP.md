## 待决问题

### D1 · 删除模块时，里面的任务去哪？—— **已定：确认后一并删除**

- 结论：删除模块/子模块时，组内任务**真删**（先弹窗告知条数），不退回默认。
- 已同步：`docs/specs/goal-and-requirements.md`「删除」去掉了“（推断）”；`docs/specs/architecture.md` 的 schema 把 `task.module_id` / `submodule_id` 改成 `ON DELETE CASCADE`，并写明为什么需要一条 v2 迁移（v1 已发布为 `SET NULL`，历史条目不能改）。
- 连带结论：删项目同样是“带走它的所有任务”——`project_id` 本来就是 `CASCADE`，无需迁移。

### D2 · 子模块与模块的新建入口 —— **已定：左栏右键菜单**

- 项目行右键 → 新建模块；模块行右键 → 新建子模块。
- 可做：`contextmenu` 在 Tauri 的 webview 里就是普通 DOM 事件，`preventDefault` 掉原生菜单、弹自建菜单即可（与确认框同一套 DOM 层）。

### D3 · 项目名 / 模块名怎么改 —— **已定：同一处右键菜单里的「重命名」**

- 不占用双击（双击归任务标题），也不占用单击（单击已经被“切换视图”用了）。
- 重命名走弹窗输入，不复用任务的行内编辑：结构名不常改，不值得为它再写一套行内编辑。

### D4 · 筛选落地时默认视图会变

goal 规定状态标签**默认只勾「未完成」「进行中」**，也就是说筛选做完之后，“已完成”默认**隐藏**，而现在它们一直显示（灰显 + 删除线）。这是规格要求的行为，到时候别当成 bug。

### D5 · 右键不可发现（未确认，建议的补救）

右键菜单没有任何视觉提示，第一次用的人不会知道能右键；纯键盘用户也不友好。建议：同一菜单同时挂在**鼠标悬停时出现的 `⋯` 按钮**上（一个菜单组件、两个触发器），成本很小。**尚未确认。**

阶段 4 实现决策：

- 子任务入口用父任务行的 `＋` 行内输入，回车后输入行保持打开，可连续添加；父任务行有折叠箭头、默认展开，收起状态只在本次会话内记住。
- 聚合按字面规则实现：零个子任务时 `all()` 为真，所以删除最后一个未完成子任务会让父任务变 `done`。
- 子任务优先级以父任务为上限：新建时默认"中"、父任务更低则跟随；父任务降档时级联下调仍高于它的子任务，旧数据由 v3 迁移归一。
- `create_task` / `delete_task` 的返回结构改为带 `notices` 的对象；只有父任务被自动改动时才产生提示。
- 轻提示改为 FIFO 队列，一次显示一条（info 3s / error 8s）。

阶段 6 实现决策：

- 备份只在 `0 < user_version < 最新版本` 时生成；新库与同版本启动不备份。备份失败即停止迁移。
- `PRAGMA foreign_key_check` 移进迁移事务、提交之前；失败连 `user_version` 一起回滚，下次启动仍会拒绝。
- 错误窗口用 `WebviewUrl::App("index.html?startupError=…")` 独立创建，不依赖 setup 阶段 `window.url()` 的时序；原因只取 SQLite 报错的第一行，备份路径放在最前面，两者都无需滚动即可看见。
- 删库重建不重启进程：持锁换出连接 → 删主文件与边车 → 重新打开并迁移 → 放回；保留 `.bak-*` 备份，主文件删不掉时原库接回。
- 新增单测覆盖备份生成/保留 5 份/失败带路径/重置重建/FK 校验回滚；全部 88 个后端测试通过。

阶段 8 实现决策：

- 时间存本地时间文本 `YYYY-MM-DDTHH:MM`，不存时间戳：单机单人不需要时区换算，固定格式下字符串比较就是先后；时钟用 `chrono::Local`。
- 时间是**状态写入的副产品**，不是独立字段：`write_status` 是唯一改状态的入口，在同一个 `UPDATE` 里写 `status` / `start_at` / `end_at`，规则只有一处。
- 同一状态重复写入不改写已有时间；退回未完成会清空两项，所以每次重新开始都是新的一轮。
- 没开始过就被级联 / 聚合标为已完成的任务，只记结束时间，开始保持 `NULL`，不伪造开始。
- 父任务与子任务用同一套规则；聚合自动改父任务也走 `write_status`，时间与状态不会分家。
- 表格时间列只读，点不进去；原来那版手动编辑命令 `set_task_schedule` 与 `askSchedule` 弹窗已删除，避免同一字段有两套写入口。
- 迁移 v4 只 `ALTER TABLE ADD COLUMN`，不动已有行。
- 创建时间用 v5 追加 `created_at`，同样只加列；升级前的任务保持 `NULL`，不拿迁移时刻冒充创建时间。新建任务的创建时间在 `create_task` 里与任务本体同一条 INSERT 写入。
- 表格三列时间都是只读摘要；「创建」固定在「开始」之前，列宽收紧、时间字号降到 11.5px，给任务列留出空间。
- 真实窗口用 CDP 建了一条临时任务，走完 `未完成 → 进行中 → 已完成 → 未完成`：进行中只出现开始时间，完成时开始时间保留并出现结束时间，退回未完成两项清空；创建时间在每一步都不变；每步都从真实后端读回字段核对，随后删除该任务。

阶段 9 实现决策：

- 默认窗口宽度只改 `width`，高度 720 与最小宽度 720 不动；列宽调整让窄窗口也能用。
- 列宽保存为固定列的像素值，`任务` 列不存：它永远按“容器宽度 − 其余列”计算，所以窗口缩放只影响它，其他列保持用户设定。
- 表头只给相邻两列之间加分界线，不提供“拖到窗口外变宽”的行为；拖动两侧同时收放，总宽度不变。
- 任务行右键用上下文坐标弹菜单；从菜单选「移动到…」时关掉根菜单，在原坐标重开移动树。行内输入框上的右键保留给输入框，不弹任务菜单。
- 去掉行尾操作列后，分组行与子任务输入行的 `colSpan` 从 8 改为 7。
- 分割线常驻：表头 1px 深线、正文 1px 浅线；拖动把手 9px 宽，悬停时把线两侧的表头一起点亮。
- 拖动时浮层显示两列当前宽度（如 `创建 152px · 开始 80px`），让“两侧一起变”可见；松开即收起。
- 最小列宽放宽到 36–100px，给拖动留出空间；时间列过窄时用省略号，完整值仍在悬停标题里。
- 时间列字号从 11.5px 提到 13px，默认宽度从 116px 提到 128px，保证 16 位时间在默认布局下完整显示。
- 列序把优先级移到创建 / 开始 / 结束之前；表头分界线同步改为 `title:priority`、`priority:created` 等，拖动逻辑本身不变。
- 任务标题与备注摘要统一到 13px；双击改名与行内新增子任务的输入框也同步 13px，避免进入编辑时字号跳变。
